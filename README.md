# Система управления банковскими картами

## Принятые решения в разработке

При разработке системы управления банковскими картами были приняты следующие архитектурные и технологические решения:

### 1. **MapStruct для маппинга объектов**
В качестве основного инструмента для преобразования между DTO и сущностями используется **MapStruct**. Этот инструмент генерирует эффективный код маппинга на этапе компиляции, обеспечивая:
- Высокую производительность
- Безопасность типов
- Легкость поддержки и рефакторинга

### 2. **Query Builder Service для фильтрации**
Для основного сервиса управления картами был разработан специализированный **QB (Query Builder) сервис**, предназначенный для реализации разнообразных фильтров с использованием **Java Criteria API**. Это решение позволяет:
- Динамически строить сложные запросы к базе данных
- Добавлять новые фильтры без изменения существующего кода
- Обеспечивать гибкость в поиске и фильтрации данных
- Поддерживать масштабируемость системы

#### Я решил использовать именно эти технологии, так как посчитал их самыми достойными из аналогов. Касательно других аспектов все сделано по README.md который был прикреплен до этого.

## Запуск проекта в Docker


    ```
   git clone https://github.com/starkovsavva/bankresttest.git
    ```


   ```bash
   docker-compose up --build
   ```
   
   После успешного запуска приложение будет доступно по адресу:
   - **API**: http://localhost:8080
   - **Swagger UI**: http://localhost:8080/swagger-ui.html
   - **PostgreSQL**: localhost:5432 (для внешних подключений)

### Доступные endpoints

#### Аутентификация
- `POST /api/auth/sign-up` - Регистрация пользователя
- `POST /api/auth/sign-in` - Авторизация пользователя

#### Управление картами (требуется аутентификация)
- `GET /api/cards` - Получить все карты (ADMIN)
- `POST /api/cards` - Создать карту (ADMIN)
- `GET /api/cards/{id}` - Получить карту по ID (USER)
- `PUT /api/cards/{id}` - Обновить карту (ADMIN)
- `DELETE /api/cards/{id}` - Удалить карту (ADMIN)
- `GET /api/my-cards` - Получить свои карты (USER)
- `POST /api/cards/transfer` - Перевод между картами (USER)
- `PUT /api/cards/{id}/block` - Заблокировать карту (USER)


### Переменные окружения
При необходимости можно переопределить настройки через `.env` файл или переменные окружения:
- `SPRING_DATASOURCE_URL`
- `SPRING_DATASOURCE_USERNAME`
- `SPRING_DATASOURCE_PASSWORD`
- `JWT_SECRET_KEY` (для продакшена)
